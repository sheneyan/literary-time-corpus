# v0.1.0 GitHub Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the existing offline TXT scanner as a manually verified `v0.1.0` GitHub Release with a wheel and checksum.

**Architecture:** Keep release support documentation-only: adjust the README, use the existing repository and wheel tests as the quality gate, and perform one manual clean-environment smoke test. Publish an annotated tag and a draft GitHub Release only after every local check passes; verify the uploaded assets before making the draft public.

**Tech Stack:** Python 3.11, uv, pytest, Hatchling, Git, GitHub CLI, SHA-256

### Task 2: Run the manual release gate and build assets

- [ ] **Step 2: Run the complete tests and build the wheel**

Run:

```bash
uv sync --locked
uv run pytest -q
uv build --wheel
```

Expected: the full suite passes and the named v0.1.0 wheel is created.

- [ ] **Step 3: Install and smoke-test outside the repository**

Create a private temporary directory, copy the synthetic TXT fixture into it,
create a new virtual environment there, and install only the built wheel:

```bash
repo_dir=$(pwd)
release_verify_dir=$(mktemp -d /tmp/ltc-v010.XXXXXX)
chmod 700 "$release_verify_dir"
cp tests/fixtures/extract/times.txt "$release_verify_dir/input.txt"
python3 -m venv "$release_verify_dir/venv"
"$release_verify_dir/venv/bin/python" -m pip install \
  dist/literary_time_corpus-0.1.0-py3-none-any.whl
cd "$release_verify_dir"
"$release_verify_dir/venv/bin/ltc" --help
"$release_verify_dir/venv/bin/ltc" scan input.txt --output scan
```

Expected: installation succeeds, help exits `0`, and scan reports `status=complete`.

- [ ] **Step 4: Verify package version and the exact five outputs**

Run from the temporary directory:

```bash
"$release_verify_dir/venv/bin/python" -c \
  'from importlib.metadata import version; assert version("literary-time-corpus") == "0.1.0"'
test "$(find scan -maxdepth 1 -type f | wc -l | tr -d ' ')" -eq 5
for name in normalized.json candidates.jsonl report.json review.md run.json; do
  test -f "scan/$name"
done
```

Expected: all commands exit `0`.

- [ ] **Step 5: Generate and verify the checksum**

Return to the repository and run:

```bash
cd "$repo_dir"
(
  cd dist
  shasum -a 256 literary_time_corpus-0.1.0-py3-none-any.whl > SHA256SUMS
  shasum -a 256 -c SHA256SUMS
)
```

Expected: `literary_time_corpus-0.1.0-py3-none-any.whl: OK`.

### Task 3: Merge, tag, and publish the verified GitHub Release

**Files:**
- No tracked file changes
- Upload: `dist/literary_time_corpus-0.1.0-py3-none-any.whl`
- Upload: `dist/SHA256SUMS`

- [ ] **Step 1: Merge the release branch and reverify main**

From the main worktree, update `main`, merge the completed release branch, and
run the full suite again:

```bash
git switch main
git pull --ff-only
git merge --no-ff docs/v0.1-release-design -m "docs: prepare v0.1 GitHub release"
uv run pytest -q
git status --short --branch
```

Expected: tests pass and `main` is clean and ahead of `origin/main`.

- [ ] **Step 2: Push main and create the annotated tag**

First confirm that the release tag does not already exist, then publish the
verified commit and tag:

```bash
test -z "$(git ls-remote --tags origin refs/tags/v0.1.0)"
git push origin main
git tag -a v0.1.0 -m "Literary Time Corpus v0.1.0"
git push origin v0.1.0
```

Expected: both pushes succeed and `v0.1.0` resolves to the verified main commit.

- [ ] **Step 3: Create a draft release with the two assets**

Run:

```bash
gh release create v0.1.0 \
  --verify-tag \
  --draft \
  --title "v0.1.0" \
  --notes "First public release of the offline TXT scanner. It normalizes a user-supplied UTF-8 text, extracts literary time candidates, and writes normalized.json, candidates.jsonl, report.json, review.md, and run.json. Scan output is analysis, not publication approval. Verified on macOS 26.5 arm64 with Python 3.11.16 and uv 0.10.0; other environments are untested." \
  dist/literary_time_corpus-0.1.0-py3-none-any.whl \
  dist/SHA256SUMS
```

Expected: GitHub returns the draft release URL.

- [ ] **Step 4: Verify uploaded assets before publication**

Run:

```bash
release_asset_dir=$(mktemp -d /tmp/ltc-v010-assets.XXXXXX)
chmod 700 "$release_asset_dir"
gh release download v0.1.0 --dir "$release_asset_dir"
cd "$release_asset_dir"
shasum -a 256 -c SHA256SUMS
gh release view v0.1.0 --json isDraft,tagName,assets,url
```

Expected: checksum reports `OK`, `isDraft` is `true`, the tag is `v0.1.0`, and
the asset list contains exactly the wheel and `SHA256SUMS`.

- [ ] **Step 5: Publish and verify the release**

Run:

```bash
gh release edit v0.1.0 --draft=false
gh release view v0.1.0 --json isDraft,tagName,assets,url
```

Expected: `isDraft` is `false` and the two verified assets remain attached.

If any upload or checksum check fails, do not run the publish command; leave the
release as a draft and report the exact failure.
